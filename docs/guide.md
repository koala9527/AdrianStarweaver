# 《咒语旅团》H5 单机游戏架构文档

## 1. 文档目标

本文档用于指导一个 **PC 端 H5 单机版** 的开发。

目标不是完整复刻《咒语旅团》，而是基于其核心体验，提炼出一个可快速验证的 Demo：

- 核心验证点：**1 个角色 + 咒语构筑系统是否好玩**
- 平台：PC 浏览器 H5
- 类型：俯视角、轻肉鸽、生存刷怪、自动施法、构筑成长
- 联机：**不做**
- 后端：**不做**
- 数据存储：本地 `LocalStorage`

---


家唯一能主动做的事就是“位移”。

绝对约束：去除所有攻击键、技能键、交互键。

交互逻辑：攻击是自动的，拾取是自动的。甚至升级分支的选择、事件的触发、对话的推进，都必须通过玩家在空间上的“物理位移”来达成。

语义化实时反馈怪物将实时监测玩家的属性（法强、血量、元素倾向）与走位频率，通过对白气泡反馈：优势压制：当玩家构建出高频火系 Build 时，边缘怪物会喊出：“空气在燃烧！快散开！”并产生真实的逃跑行为。弱点补刀：当玩家血量低于 $20\%$ 且位移停滞时，怪群会集体发出嘲讽：“他跑不动了！围死这个学徒！”针对性引导：如果玩家错过了远处的关键资源，AI 引导怪会通过对白提示：“他在害怕那堆余烬吗？胆小鬼！”


## 2. 玩法参考拆解

结合《咒语旅团》（The Spell Brigade）的公开资料，可以抽象出以下高价值玩法特征：

1. **俯视角群怪生存**：玩家在大批敌人中移动、生存、输出。
2. **法术驱动战斗**：角色不是依赖普通攻击，而是靠自动/半自动释放的法术持续清场。
3. **升级三选一构筑**：每次升级从多个强化中选择，逐渐形成一局内 Build。
4. **元素/词条协同**：法术本体、元素附魔、遗物、被动效果之间形成联动。
5. **局内成长 + 局外轻成长**：单局体验紧凑，同时可保留少量永久解锁。
6. **任务事件驱动节奏**：不是只刷怪，还会穿插精英、目标点、Boss 等阶段事件。

本 Demo 只保留最关键的四层：

- **角色底盘**
- **法术系统**
- **升级构筑**
- **刷怪/事件节奏**

---

## 3. Demo 产品定义

## 3.1 一句话定义

玩家操控一名法师在一张封闭地图中生存 5 分钟，通过不断升级、选择新法术、强化法术、组合元素与遗物，形成一套能够清怪、打精英、击杀 Boss 的咒语构筑。

## 3.2 验证目标

本 Demo 主要验证以下问题：

1. 玩家是否能快速理解“**移动 + 自动施法 + 升级构筑**”的循环。
2. 法术成长是否能产生明显的“越来越爽”的强度爬坡。
3. 不同法术与元素组合是否能形成可感知的 Build 差异。
4. 单局 10~12 分钟的节奏是否足够紧凑。
5. H5 版本在 PC 浏览器中是否能稳定承载百怪同屏与弹幕特效。

## 3.3 最小可玩范围（MVP）

- 角色：1 个
- 主地图：1 张
- 游戏模式：1 个生存模式
- 基础法术：6 个
- 元素类型：4 个
- 法术强化项：24~30 个
- 遗物：8~12 个
- 敌人：6 种普通怪 + 2 种精英 + 1 个 Boss
- 单局流程：开始 -> 生存 -> 升级构筑 -> 精英事件 -> Boss -> 结算

## 4. 核心体验与设计原则

## 4.1 核心体验

玩家每 20~40 秒都应获得一次正反馈：

- 升级
- 获得新法术
- 法术形态变化
- 元素联动成型
- 清怪效率大幅提高
- 精英/Boss 被快速融化

## 4.2 设计原则

### 原则 A：构筑优先于操作

操作要求低，但走位仍重要。爽点来自：

- 选对强化
- 拼出联动
- 看到法术从“能打”成长到“清屏”

### 原则 B：单局成长必须清晰

每次升级都应至少带来以下之一：

- 数值变强
- 形态变化
- 触发频率提升
- 新联动开启

### 原则 C：构筑选择要少而有效

Demo 不追求海量内容，而追求：

- 选项容易理解
- 选项之间有明显风格差异
- 选项能组合出套路

### 原则 D：战场信息要清楚

虽然是弹幕/刷怪型游戏，但屏幕信息要可读：

- 玩家技能效果颜色统一
- 敌方危险区域明确
- 可捡物、经验球、升级提示显眼

## 5. 游戏循环设计

## 5.1 局外循环（极简）

1. 进入标题界面
2. 选择开始游戏
3. 可查看已解锁法术/遗物图鉴
4. 开局前选择一项初始倾向（可选）
5. 进入战斗
6. 结算获得少量局外解锁点数
7. 解锁新法术池/遗物池/初始强化

说明：
局外系统要轻，不让玩家在 H5 Demo 阶段把注意力转移到数值养成，而是聚焦单局 Build。

## 5.2 局内循环（核心）

1. 玩家移动躲避敌人
2. 角色自动释放法术
3. 击杀敌人掉落经验
4. 玩家升级，触发三选一
5. 选择以下一种成长：
   - 获取新法术
   - 升级已有法术
   - 获得元素灌注
   - 获得遗物/全局被动
6. 随时间触发事件：精英、目标守点、小 Boss
7. 最终 Boss 出现
8. 结算并统计 Build

## 5.3 单局时间轴（建议 12 分钟）

- `00:00 - 02:00`：教学感阶段，怪少、让玩家拿到第 2 个法术
- `02:00 - 04:00`：开始形成第一轮 Build，出现第一只精英
- `04:00 - 07:00`：怪潮增强，玩家开始补齐第 3、第 4 个法术位
- `07:00 - 09:00`：事件压力提升，出现区域危险机制
- `09:00 - 11:00`：高压刷怪，推动玩家完成核心联动
- `11:00 - 12:00`：Boss 战与收尾结算

## 6. 角色设计

## 6.1 角色定位

Demo 只做一个角色：**见习咒术师**。

角色特点：

- 中等移速
- 自动施法
- 初始自带 1 个签名法术
- 可在局内获得最多 4 个法术槽

## 6.2 基础属性

建议基础属性如下：

- 最大生命：`100`
- 移动速度：`220`
- 基础法强：`1.0`
- 冷却缩减：`0%`
- 拾取半径：`80`
- 暴击率：`5%`
- 暴击伤害：`150%`
- 护盾：`0`
- 生命回复：`0.5/s`

## 6.3 角色成长方向

角色本体不做复杂技能树，只承担 Build 容器的作用：

- 提高生存
- 容纳法术
- 承接遗物与元素词条

---

## 7. 法术构筑系统

这是 Demo 最核心的系统。

## 7.1 法术系统目标

法术系统需要满足四个要求：

1. **容易懂**：玩家一眼知道法术做什么。
2. **能升级**：同一法术升级后有明显变化。
3. **能联动**：法术之间共享元素、状态或触发器。
4. **能分流派**：让 Build 呈现不同方向，而非单纯堆数值。

## 7.2 法术槽设计

- 初始法术槽：`1`
- 最大法术槽：`4`
- 第 1 个法术为角色签名法术
- 其余法术通过升级选项获取

法术槽位建议：

1. **主力输出法术**
2. **范围清怪法术**
3. **控制/持续伤害法术**
4. **爆发/召唤/辅助法术**

## 7.3 法术结构模型

每个法术由以下字段组成：

```ts
type SpellConfig = {
  id: string;
  name: string;
  rarity: 'common' | 'rare' | 'epic';
  tags: string[];
  element?: 'fire' | 'ice' | 'arcane' | 'lightning';
  castMode: 'auto' | 'interval' | 'trigger';
  targetMode: 'nearest' | 'random' | 'area' | 'surround';
  baseDamage: number;
  cooldown: number;
  projectileSpeed?: number;
  projectileCount?: number;
  duration?: number;
  radius?: number;
  pierce?: number;
  chain?: number;
  statusEffects?: StatusEffectConfig[];
  upgrades: string[];
}
```

## 7.4 推荐 Demo 法术池（6 个）

### 1）奥术飞弹

- 类型：单体追踪
- 定位：稳定输出、开局友好
- 特征：自动锁定最近敌人
- 升级方向：多弹、分裂、追踪强化、暴击联动

### 2）火焰新星

- 类型：近身范围
- 定位：清怪/防贴脸
- 特征：围绕自身爆发一圈火焰
- 升级方向：扩大半径、附加点燃、二段爆炸

### 3）寒冰棱镜

- 类型：穿透直线
- 定位：中距离穿线清怪
- 特征：直线发射、可冻结
- 升级方向：穿透、碎裂、冻结概率、冰爆

### 4）闪电链

- 类型：弹射
- 定位：对密集怪群效率高
- 特征：命中后链到附近目标
- 升级方向：弹射次数、感电、暴击连锁

### 5）虚空法阵

- 类型：区域持续伤害
- 定位：地面控场
- 特征：在目标区域生成持续法阵
- 升级方向：持续时间、范围、减速、叠层增伤

### 6）秘能使魔

- 类型：召唤/辅助输出
- 定位：补充自动攻击与触发器
- 特征：使魔环绕或自主射击
- 升级方向：召唤物数量、攻速、继承法强、触发协同

## 7.5 法术升级类型

每个法术升级可分为四层：

### A. 数值升级

- 伤害提升
- 冷却缩减
- 投射物数量增加
- 持续时间增加

### B. 形态升级

- 飞弹分裂
- 爆炸范围扩大
- 电链额外弹射
- 法阵从单个变双阵

### C. 元素升级

- 火：点燃、爆炸、持续灼烧
- 冰：减速、冻结、碎裂
- 雷：连锁、感电、暴击联动
- 奥术：穿透、复制、回响

### D. 触发升级

- 暴击时追加施法
- 击杀时触发爆炸
- 对精英命中叠易伤
- 冻结敌人时触发落雷

## 7.6 Build 构成公式

一套 Build =

`角色底盘 + 4个法术槽 + 法术升级 + 元素灌注 + 遗物 + 全局属性`

Demo 的爽点来自以下三类组合：

1. **同元素叠加流**：如火焰持续伤害流
2. **状态触发流**：如冻结后爆裂、感电后连锁
3. **施法频率流**：如多段触发、快速循环、召唤协同

## 8. 升级与奖励系统

## 8.1 升级来源

- 普通怪掉经验球
- 精英掉大量经验
- 事件完成直接奖励一次升级或遗物

## 8.2 升级选项池

每次升级默认出现 `3 选 1`。

候选类型权重建议：

- 已有法术升级：`45%`
- 新法术获取：`20%`
- 全局属性强化：`20%`
- 遗物：`10%`
- 回复/保护类应急项：`5%`

说明：
若玩家法术槽未满，则“新法术获取”权重可动态提升。

## 8.3 选项生成规则

升级选项必须遵循以下逻辑：

1. 不给不可用选项。
2. 优先给与当前 Build 有协同的选项。
3. 控制重复率，避免连续 3 次全是废牌。
4. 当前血量过低时，提高生存项出现概率。
5. 当前已有元素偏向明显时，提高对应元素强化概率。

## 8.4 推荐升级池结构

### 法术升级卡

示例：

- 奥术飞弹 +1 发
- 火焰新星范围 +25%
- 闪电链额外弹射 +2
- 虚空法阵持续时间 +40%

### 元素灌注卡

示例：

- 你的非火焰法术首次命中附加点燃
- 你的冰系效果有 15% 概率冻结
- 雷系暴击后向附近 1 名敌人溅射

### 全局成长卡

示例：

- 法强 +12%
- 冷却缩减 +8%
- 暴击率 +10%
- 拾取范围 +30%
- 最大生命 +20

### 遗物卡

示例：

- 连击棱镜：连续命中同一目标时伤害递增
- 炽焰余烬：击杀点燃目标会爆炸
- 静电回路：感电目标死亡时向周围扩散感电
- 法术沙漏：每释放 8 次法术，下次法术伤害翻倍

## 9. 战斗系统设计

## 9.1 战斗目标

战斗系统要服务于构筑，而不是做高操作门槛动作游戏。

玩家操作仅保留：

- WASD 移动
- 鼠标用于 UI 选择
- 可选：空格冲刺（Demo 可不做）

施法方式：

- 默认全自动
- 按冷却自动释放
- 根据法术配置自动选目标

## 9.2 伤害计算建议

基础公式：

`最终伤害 = 基础伤害 × 法强系数 × 技能倍率 × 暴击倍率 × 易伤倍率 × 随机浮动`

建议控制随机浮动较小：

- 随机浮动：`0.95 ~ 1.05`

这样更利于玩家感知 Build 强度。

## 9.3 状态效果

建议 Demo 只做 4 种：

- **点燃**：持续掉血
- **冻结**：短暂定身
- **感电**：后续被雷系命中时追加链伤
- **易伤**：受到伤害增加

## 9.4 战斗可读性策略

- 玩家法术颜色固定按元素区分
- 精英怪描边或头顶标识
- Boss 危险技能提前地面预警
- 特效优先保证读性，不追求过量粒子

## 10. 敌人与关卡节奏

## 10.1 敌人设计目标

敌人不是复杂 AI，而是战斗压强的来源。

每种敌人只需承担 1 个明确作用：

- 逼走位
- 破阵型
- 吸收输出
- 制造优先击杀目标

## 10.2 敌人配置建议

### 普通怪

1. **小史莱姆**：低血量、快速靠近
2. **骷髅兵**：均衡单位
3. **盾甲怪**：高血量、慢速推进
4. **远程术士**：定时发射投射物
5. **冲锋兽**：短暂蓄力后直线冲撞
6. **分裂虫**：死亡分裂为小单位

### 精英怪

1. **冰冠守卫**：带范围减速圈
2. **雷暴祭司**：周期召唤落雷

### Boss

1. **混沌监察者**
   - 机制 1：扇形弹幕
   - 机制 2：召唤小怪
   - 机制 3：区域爆炸预警

## 10.3 刷怪导演系统（Director）

刷怪不建议写死到秒级脚本，而使用“导演系统”：

- 输入：游戏时间、玩家等级、当前输出效率、场上敌人数
- 输出：下一波刷怪配方

导演系统控制项：

- 总刷怪点数预算
- 怪物组合权重
- 精英生成时机
- 场上最大怪物数

示例：

```ts
spawnBudget = baseBudgetByTime * playerPowerAdjust * intensityFactor;
```

其中：

- `baseBudgetByTime`：随时间增长
- `playerPowerAdjust`：根据玩家强度动态微调
- `intensityFactor`：当前波次压力系数

这样可以避免：

- 玩家太强时游戏无聊
- 玩家太弱时突然被淹没

## 11. 事件系统

为了避免纯刷怪疲劳，加入轻事件。

## 11.1 Demo 事件类型

### 事件 A：精英狩猎

- 刷出 1 只精英
- 击杀后掉落遗物或高品质升级

### 事件 B：守护法阵

- 地图出现一个圆形区域
- 玩家在区域内停留累计进度
- 完成后获得免费升级

### 事件 C：能量裂隙

- 地图随机出现裂隙点
- 击破后掉大量经验球

## 11.2 事件触发时机

- 第 3 分钟：精英狩猎
- 第 6 分钟：守护法阵
- 第 9 分钟：双精英或强化事件
- 第 11 分钟：Boss 预热

---

## 12. 局外成长（极简版）

虽然不做后端，但可以做轻度本地成长，提升复玩意愿。

## 12.1 数据存储方式

使用浏览器 `LocalStorage`：

- 已解锁法术
- 已解锁遗物
- 最高生存时间
- 击杀统计
- 总资源数

## 12.2 局外成长内容

只做以下 3 类：

1. 解锁新法术加入局内卡池
2. 解锁新遗物加入局内卡池
3. 初始小加成（三选一开局偏好）

不要做：

- 大量永久数值堆叠
- 复杂天赋树
- 重氪式长期养成结构

---

## 13. H5 技术架构设计

## 13.1 技术选型建议

推荐：

- 引擎：`Phaser 3`
- 语言：`TypeScript`
- UI：`Phaser UI + DOM Overlay` 或轻量 React 外挂 UI
- 构建：`Vite`
- 数据：本地 JSON / TS Config
- 存档：`LocalStorage`

推荐 Phaser 3 的原因：

- 适合 2D 俯视角战斗
- 资源轻量，适合 H5 Demo
- 场景、对象池、碰撞、相机、粒子支持成熟
- 开发效率高于从零写 Canvas

## 13.2 客户端模块分层

建议采用“数据驱动 + 系统分层”的轻架构。

### 表现层

- 场景切换

## 14.1 RunScene 场景职责

`RunScene` 负责一局游戏的完整调度：

## 14.3 SpellSystem 设计

职责：

- 管理法术冷却
- 自动选目标
- 生成投射物/范围效果
- 应用升级结果
- 分发“施法事件”给遗物或其他系统监听

核心流程：

1. 遍历玩家装备法术
2. 判断冷却是否完成
3. 根据 `targetMode` 选目标
4. 生成对应实体
5. 结算命中、状态、伤害
6. 触发额外效果

## 14.4 BuildSystem 设计

职责：

- 管理当前 Build 组成
- 应用升级卡对玩家或法术的修改
- 维护元素标签与协同关系
- 提供当前 Build 摘要给 UI

建议：
BuildSystem 不直接做渲染，只负责“数值与规则改写”。

## 14.5 LevelUpSystem 设计

职责：

- 接收经验变更
- 判断是否升级
- 暂停战斗
- 动态生成候选卡牌
- 处理玩家选择
- 恢复战斗

候选生成算法建议：

1. 先根据当前状态构建候选池
2. 对候选按“协同权重”打分
3. 去重
4. 按稀有度与协同分混合抽取 3 个

评分维度示例：

- 与现有法术共享标签：`+2`
- 与已有遗物联动：`+3`
- 玩家当前缺少清怪能力时，AOE 升级：`+2`
- 玩家生命低时，保命卡：`+3`

## 14.6 CombatSystem 设计

职责：

- 伤害计算
- 暴击判定
- 状态附加
- 击杀回调
- 掉落与经验分发

建议使用事件化回调：

- `onSpellCast`
- `onHit`
- `onKill`
- `onCrit`
- `onStatusApply`

这样方便遗物和升级效果进行订阅触发。

## 14.7 SpawnDirector 设计

职责：

- 按时间生成怪物
- 维持场上怪物密度
- 在特定节点插入精英/Boss/事件

输入参数：

- `elapsedTime`
- `playerLevel`
- `killsPerMinute`
- `currentEnemyCount`
- `dangerState`

输出：

- 下一批敌人类型
- 数量
- 刷新位置
- 是否附加精英词缀

## 15. 数据驱动设计

为了提高扩展效率，建议所有内容配置化。

## 15.1 配置分类

- `spells.ts`：法术基础数据
- `spellUpgrades.ts`：法术升级卡
- `relics.ts`：遗物配置
- `enemies.ts`：敌人属性与行为模板
- `events.ts`：事件时间表与奖励
- `progression.ts`：局外解锁定义

## 15.2 升级卡数据结构

```ts
type UpgradeCard = {
  id: string;
  name: string;
  description: string;
  category: 'new_spell' | 'spell_upgrade' | 'global_stat' | 'element' | 'relic' | 'survival';
  rarity: 'common' | 'rare' | 'epic';
  weight: number;
  requires?: Requirement[];
  excludes?: string[];
  tags?: string[];
  apply: ApplyInstruction[];
};
```

## 15.3 配置式 ApplyInstruction

推荐使用半声明式结构，而不是把所有升级都写成硬编码 if/else：

```ts
type ApplyInstruction = {
  target: 'player' | 'spell' | 'tag';
  targetId?: string;
  operation: 'add' | 'mul' | 'set' | 'append_tag';
  field: string;
  value: number | string;
};
```

优点：

- 扩内容成本低
- 更容易调平衡
- 更适合 Demo 快速迭代

## 17. 数值与平衡建议

## 17.1 早期体验目标

开局 2 分钟内，玩家应该做到：

- 理解自动施法
- 获得至少 2 次升级
- 拿到第 2 个法术或关键强化

## 17.2 中期体验目标

第 4~8 分钟时，玩家应明显感到：

- 自己开始拥有流派倾向
- 场面从单点击杀过渡到成片清怪
- 精英需要优先处理

## 17.3 后期体验目标

第 8~12 分钟时，玩家应感到：

- 构筑已基本成型
- 普通怪不再是主要问题，Boss/危险机制才是压力源
- 自己的 Build 在伤害表现上有鲜明特色

## 17.4 平衡关注点

重点避免：

- 新法术过弱，导致玩家永远只升初始法术
- 遗物过强，法术本身反而不重要
- 升级选项废牌率过高
- 屏幕过乱导致“明明变强了却感知不到”

## 20. 风险与规避方案

## 风险 1：法术很多，但手感差不明显

规避：

- 优先做“形态差异”而不是只加数值
- 每个法术至少 1~2 个强感知升级

## 风险 2：H5 同屏性能不足

规避：

- 使用对象池
- 限制同屏投射物数量
- 怪物使用简化碰撞
- 特效分层与可降级开关

## 风险 3：升级选择看不懂

规避：

- 卡牌描述模板化
- 显示法术图标和联动标签
- 新手阶段优先给直观强化

## 风险 4：内容少导致重复快

规避：

- 先做“可组合内容”而不是堆条目数
- 强化元素协同与随机性

## 21. 最终建议的 Demo 定义

如果只做一版最值得验证的内容，我建议最终锁定为：

- **1 个角色**：见习咒术师
- **1 张地图**：封闭遗迹战场
- **1 个模式**：12 分钟生存
- **6 个法术**
- **4 个元素**
- **30 张左右升级卡**
- **10 个左右遗物**
- **6 普通怪 + 2 精英 + 1 Boss**
- **3 个局内事件**
- **本地解锁与图鉴**

这个范围对于 H5 PC Demo 来说足够完整，且真正能验证“角色 + 咒语构筑系统”的可玩性。
