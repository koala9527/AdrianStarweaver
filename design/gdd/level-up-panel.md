# Level-Up Panel

> **Status**: Designed
> **Author**: user + Claude

> **Implements Pillar**: 构筑优先于操作 (Build over Execution) — this IS the build decision interface; every level-up choice flows through this panel

## Overview

The Level-Up Panel is a modal UI overlay that appears when the player levels up. It receives 3 `UpgradeCard` objects from the Upgrade Pool System, displays them as visually distinct selectable cards, and returns the player's choice to the XP & Level-Up System which emits `UPGRADE_CHOSEN`. The panel is the single most important UI in the game — it's where every build decision happens. It renders as a UI layer within RunScene (not a separate scene), coexisting with the HUD.

## Player Fantasy

Three glowing cards fan out before you. Each one promises power — a spell upgrade, a new ability, a stat boost. You read the descriptions, weigh the synergies, and pick the one that fits your build. The card flies into your character and you feel the power immediately. The fantasy is: "I'm the architect of my own power."

## Detailed Design

### Core Rules

1. The Level-Up Panel is a Phaser Container on the RunScene UI camera, rendered above the HUD layer.

2. **Card Layout**: 3 cards displayed horizontally centered on screen.
   - Card size: 180×260px each
   - Gap between cards: 24px
   - Total width: 3×180 + 2×24 = 588px, centered at x:640
   - Vertical center: y:360 (screen center)
   - Semi-transparent dark overlay (alpha 0.6) behind cards covering full screen

3. **Card Display** (from UpgradeCard interface in Upgrade Pool System):
   - Card border color by rarity: common=white, rare=blue, epic=purple
   - Card header: `name` (top, bold)
   - Card icon: category-based icon (spell icon for spell_upgrade/new_spell, stat icon for global_stat, relic icon for relic, heart for survival)
   - Element tint on icon if card has element association
   - Card body: `description` text (short sentence per guide.md §16.2)
   - Card footer: rarity label + synergy tags displayed as small pills
   - "Recommended" tag shown if card shares 2+ tags with current build (guide.md §16.2 synergy hint)

4. **Entrance Animation**: Cards fly in from bottom of screen with staggered timing (0ms, 80ms, 160ms), scale from 0.5→1.0 with easeOutBack, total animation ~400ms. Panel is not interactive until entrance animation completes.

5. **Selection**:
   - Mouse hover: card scales up 1.0→1.08, slight glow, tooltip not needed (description is on card)
   - Mouse click: selects the card
   - Keyboard: 1/2/3 keys select left/center/right card

6. **Selection Animation**: Chosen card scales up and flies toward screen center, unchosen cards fade out. Total ~300ms. After animation completes, emit the selection.

7. **Selection Flow**:
   ```
   1. Player clicks/presses a card
   2. Panel plays selection animation
   3. Panel calls the selection callback provided by XP & Level-Up System
   4. XP & Level-Up System emits UPGRADE_CHOSEN { card }
   5. XP & Level-Up System checks pendingLevelUps
   6. If more pending: Panel receives 3 new cards, plays entrance animation again
   7. If none pending: Panel hides, game resumes
   ```

8. **Multi-Level-Up**: The panel stays open between consecutive level-ups. A "Level X" indicator updates between each card set. The level counter is displayed above the cards.

9. **Input Lock**: During entrance and selection animations, input is disabled to prevent double-selection or premature clicks.

### States and Transitions

| State | Entry | Exit | Behavior |
|-------|-------|------|----------|
| **Hidden** | Default / after all level-ups resolved | Level-up triggered | Invisible, no input |
| **Animating In** | Cards received from Upgrade Pool | Animation complete (~400ms) | Cards flying in, input locked |
| **Awaiting Selection** | Entrance animation done | Player selects a card | Cards interactive, hover effects active |
| **Animating Out** | Card selected | Animation complete (~300ms) | Selection animation, input locked |
| **Transitioning** | Out animation done, more pending | New cards received | Brief pause, then Animating In again |

### Interactions with Other Systems

| System | Direction | Interface |
|--------|-----------|-----------|
| XP & Level-Up System | Called by | Receives 3 `UpgradeCard` objects + selection callback |
| Upgrade Pool System | Indirect | Cards are generated by Upgrade Pool, passed through XP & Level-Up |
| Build System | Indirect | Selection triggers `UPGRADE_CHOSEN` via XP & Level-Up System |
| Event Bus | Emits (indirect) | Selection flows through XP & Level-Up → `UPGRADE_CHOSEN` + `LEVEL_UP` |
| HUD | Coexists | HUD remains visible beneath the panel overlay |

## Formulas

### Card Positioning
```
totalWidth = CARD_COUNT × CARD_WIDTH + (CARD_COUNT - 1) × CARD_GAP
cardX[i] = screenCenterX - (totalWidth / 2) + i × (CARD_WIDTH + CARD_GAP) + CARD_WIDTH / 2
cardY = screenCenterY
```

With defaults (CARD_COUNT=3, CARD_WIDTH=180, CARD_GAP=24):
```
totalWidth = 588
cardX[0] = 640 - 294 + 0 + 90 = 436
cardX[1] = 640 - 294 + 204 + 90 = 640
cardX[2] = 640 - 294 + 408 + 90 = 844
```

| Variable | Type | Range | Description |
|----------|------|-------|-------------|
| CARD_WIDTH | int | 180 | Card width in pixels |
| CARD_HEIGHT | int | 260 | Card height in pixels |
| CARD_GAP | int | 24 | Gap between cards |
| CARD_COUNT | int | 3 | Always 3 cards |
| screenCenterX | int | 640 | Half of 1280 base width |
| screenCenterY | int | 360 | Half of 720 base height |

## Edge Cases

| Scenario | Expected Behavior | Rationale |
|----------|------------------|-----------|
| Player clicks during entrance animation | Input ignored (locked) | Prevent premature selection |
| Player clicks during exit animation | Input ignored (locked) | Prevent double selection |
| Multi-level-up (3 levels at once) | Panel stays open, shows 3 new cards after each selection, level counter updates | Queued level-ups from XP & Level-Up System |
| All 3 cards are same rarity | All borders same color — no special handling | Visual consistency |
| Card description too long | Text truncated with ellipsis at 2 lines max | Prevent layout overflow |
| Player presses 1/2/3 before animation done | Input ignored (locked) | Same as mouse click lock |
| Browser loses focus during panel | Panel persists — game is paused anyway | No state loss |
| "Recommended" tag on multiple cards | All qualifying cards show the tag | Player decides which synergy to pursue |

## Tuning Knobs

| Parameter | Current Value | Safe Range | Effect of Increase | Effect of Decrease |
|-----------|--------------|------------|-------------------|-------------------|
| `CARD_WIDTH` | 180px | 140–220px | Larger cards | Smaller cards |
| `CARD_HEIGHT` | 260px | 200–320px | Taller cards | Shorter cards |
| `CARD_GAP` | 24px | 12–40px | More space between cards | Tighter layout |
| `ENTRANCE_DURATION` | 400ms | 200–600ms | Slower entrance | Faster entrance |
| `ENTRANCE_STAGGER` | 80ms | 40–150ms | More stagger between cards | Near-simultaneous |
| `EXIT_DURATION` | 300ms | 150–500ms | Slower exit | Faster exit |
| `HOVER_SCALE` | 1.08 | 1.04–1.15 | More pronounced hover | Subtler hover |
| `OVERLAY_ALPHA` | 0.6 | 0.3–0.8 | Darker background | More transparent |
| `SYNERGY_TAG_THRESHOLD` | 2 | 1–3 | "Recommended" shown less often | Shown more often |
